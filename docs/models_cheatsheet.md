# 何を回して何と比べているのか（早見表）

`progress_20260925.md` の表に出てくる B0 / B1 / B2 / B3 / B3s / B4 / ORC / ①〜④ / hybrid の定義。
コードの実体：`bposd_baseline.py`, `leak_baselines.py`, `leak_hmm.py`, `model.py`, `evaluate.py`

## 0. 一番大事な一行

**B0・B1・B2・B3・B3s・B4・ORC・hybrid は、全部おなじ BP-OSD デコーダである。**
違うのは **BP-OSD に渡す「測定ごとの誤り確率 $p_S$」をどう作るか**、それだけ。

```
1 ショットの IQ 点 576 個 ──► [ p_S の作り方が B0〜B4/ORC/hybrid で違う ] ──► 事前確率の更新（式19）
                          └─► 硬判定 → 検出器 504 ───────────────────────► BP-OSD ──► 論理 12 ビット
```

`bposd_baseline.update_priors()` の 1 行がその接点：

$$p'_i = p_{S,i}(1-p_i) + p_i(1-p_{S,i})\qquad\text{(Riverlane 式19)}$$

- $p_i$ = Stim の DEM が出す「その測定に付く回路誤りの確率」（全手法で共通、動作点で決まる）
- $p_{S,i}$ = **「その測定の読み出しを取り違えた確率」** ← **ここだけが手法ごとに違う**

**別物のデコーダは 2 つだけ**：
1. **BP-OSD**（`ldpc` ライブラリ、`schedule="serial"`）… 上の図の箱。1 ショット 6.3 s
2. **学習型 Transformer**（`model.py`、自作）… IQ から直接 12 ビットを出す。1 ショット 0.7 ms

## 2. 古典ベースライン一覧（全部 BP-OSD。$p_S$ の作り方だけが違う）

| 記号 | $p_S$ の作り方 | 使っている情報 | 正体 | LER |
|---|---|---|---|---|
| **B0** | 全測定に**定数** $p_S = 0.032$（平均値） | アナログ情報を捨てる | **従来の hard デコーダ** | 0.278 |
| **B1** | $p_S = P(\text{取り違え}\mid\text{その IQ 点})=\frac{1}{1+e^{\|L\|}}$ | その 1 点の 2 状態 LLR | **先行研究の標準 soft デコーダ = 本命ライバル** | 0.159 |
| **B2** | B1 ＋「$f^{(0)}$ と $f^{(1)}$ の**両方**で密度がピークの 1% 未満 → リークと判定 → $p_S=0.5$」 | 同上＋円形の外れ値判定 | **Hanisch 論文の実際の手法** | 0.172 |
| **B3** | B1 ＋「3 状態の事後確率で $\|2\rangle$ が最大 → $p_S=0.5$」 | 同上＋$f^{(2)}$ を知った最適判別 | 理想化した「1 点判別の最善（硬判定版）」。**ρ=2.45% では一度も発火せず B1 と同一** | 0.159 |
| **B3s** | $p_S = (1-\pi)P(\text{反転}\mid\text{IQ}) + \tfrac12\pi$、$\pi=P(\text{リーク}\mid\text{IQ 1 点})$ | **判定せず確率で渡す** | **1 点情報の Bayes 最適 = per-shot の真の上限** | 0.162 |
| **B4** | 上と同じ式だが $\pi_r = P(\ell_r \mid \text{その量子ビットの 8 ラウンド分の IQ 系列})$（2 状態 HMM の前向き後向き） | **時間方向**（量子ビット単独） | **時間方向だけを使う古典最適** | 0.1345 |
| **ORC** | シミュレータの**真の** $\ell$ を見て、リークしていた測定に $p_S=0.5$ | 反則（真値） | **到達可能上限の目印**。実機では不可能 | 0.106 |

読み方：

- **B0 → B1** = soft 情報の効果（既知事実の再現）
- **B1 → B2 / B3 / B3s** = 「IQ 1 点からリークを見る」既存の発想。**B2 は悪化、B3 は発火せず、B3s は差なし → 効果 0**
- **B1 → ORC** = リークの所在が分かったときに古典側で取り返せる余地 = **0.053**（本研究の標的）
- **B4** = その余地の一部を「時間方向」だけで取った古典的な最善（0.159 → 0.1345）

## 3. あなたが作ったモデル（`model.py` `SyndromeTransformer`、1.29M パラメータ）

```
入力：トークン列（raw なら 576 個、各 (I,Q) ／ soft・hard なら 504 個、各 1 値）
       ＋ 位置 = 量子ビット埋め込み(72 種) + ラウンド埋め込み(8 種)
                         │
        Linear(→128) → Transformer Encoder ×6（pre-LN, d=128, 4 ヘッド, FFN 512）
                         │
        ├─ 論理ヘッド ：学習する 12 個のクエリが cross-attention → 12 logit
        │                 = 「論理誤りが起きたか」の予測（デコーダ本体の出力）
        └─ リークヘッド：トークンごと Linear(128→1) → 「この測定はリーク中だったか」の確率
```

- 損失 $\mathcal{L}=\mathrm{BCE}(\text{論理 12}) + \lambda\,\mathrm{BCE}(\text{リーク})$、$\lambda=1$。
  **リークの教師は §1 ② の真値 $\ell$**（シミュレータだから手に入る）
- AdamW 3e-4、warmup 1000 → cosine、bf16、batch 256、**20 万 step**、データはオンライン生成（毎 step 新規）

| 走らせた run | 入力表現 | ラウンド間 attention | 何のための条件か |
|---|---|---|---|
| **① `r1_raw_seq`** | raw (I,Q) 576 | **あり** | 本命 |
| **② `r2_hard_seq`** | hard 504 | あり | 軸2 の下限（アナログ無し） |
| **③ `r3_soft_seq`** | soft 504 | あり | 軸2 の中間（$\boxplus$ で潰した soft） |

## 4. モデルの使い方が 2 通りある（ここが一番混乱しやすい）

### (a) end-to-end … 論理ヘッドをそのまま答えにする
Transformer が出した 12 logit を復号結果とする。**BP-OSD は一切使わない。**

結果：① 0.417 / ② 0.515 / ③ 0.375 / ④ 0.898 **対 B1 0.159 → 大敗**。
容量不足（d=128・6 層）で、20 万 step でも曲線はまだ下降中。速さは 0.7 ms（BP-OSD の 3〜4 桁速い）。

### (b) hybrid … **リークヘッドだけ**使い、答えは BP-OSD に出させる
`evaluate.py --hybrid` の 2 行がすべて：

```python
p2  = classification_error_from_llr(shots.meas_llr)      # 1 点の取り違え確率（= B1 の中身）
p_s = (1.0 - leak_p) * p2 + 0.5 * leak_p                 # leak_p = リークヘッドの出力
```

**この式は B3s・B4・ORC とまったく同じ形。** つまり hybrid では、あなたのモデルは
**「$p_S$ を作る部品」として B3s（1 点）・B4（HMM）・ORC（真値）と同じ土俵に立つ。**
後段が全部 BP-OSD で揃うので、差はリーク推論の質だけになる。

結果：**hybrid ① = 0.1245**（B1 0.159 とオラクル 0.106 の間に入り、余地の 65% を回収）。
**これが今の主戦場。** end-to-end は「速いが弱い」として別に報告する。

## 7. つまずきやすい 3 点（2026-09-25 追記）

### 7.1 `p2 = classification_error_from_llr(shots.meas_llr)` は何か

**「この IQ 点を見て 0/1 を決めたとき、その判定が間違っている確率」** $= 1/(1+e^{|L|})$。
硬判定そのものではなく**硬判定が反転している確率**で、Riverlane 式19 の $p_S$ の本体。
IQ 点が境界の真上なら 0.5、遠ければ ~0。B0 はこれを定数 0.032 で置き換え、B1 は 1 点ごとに計算する。

### 7.2 B3 と B3s を両方用意した理由

#### (a) 舞台：測定 1 個を見ている

補助量子ビットを 1 回測ると、IQ 平面に点が 1 つ返る。例として**ちょうど真ん中（I=0）に落ちた点**を考える。
この点を出した原因は 3 つしかない。

| 仮説 | 意味 |
|---|---|
| $\lvert 0\rangle$ だった | 正常で、本当の値は 0 |
| $\lvert 1\rangle$ だった | 正常で、本当の値は 1 |
| $\lvert 2\rangle$ だった | **リーク中だった**（計算状態の外に出ていた） |

「この点を見た後で、どれだったと思うか」を確率にしたのが**事後確率**。動作点
（SNR=8.4, β=0.05, ρ=2.45%, σ=0.488）での実測：

```
I=0 の点を見た後の事後確率（合計 1.0）
  P(|0⟩ だった | この点) = 0.376
  P(|1⟩ だった | この点) = 0.466   ← 表の「P(1)=0.466」
  P(|2⟩ だった | この点) = 0.158   ← 表の「P(リーク)=0.158」
```

**注意：$P(\text{リーク})=0.158$ は「リークが起きる確率」ではない。**
「この 1 点を見た結果、この測定はリーク中だったと思われる度合い」。リークが起きる確率そのものは
事前確率 $\rho = 2.45\%$ で、点を見たことでそれが 0.158 に更新された、という関係。
（I=0 なのに $P(0)\neq P(1)$ なのは、振幅減衰 β=0.05 で $\lvert1\rangle$ が $\lvert0\rangle$ 側に裾を引くため。）

#### (b) B3 = 一番大きいものを勝者に選ぶ（argmax）

**「3 つのうち最大が $\lvert2\rangle$ なら、その測定をリークと断定して $p_S = 0.5$ にする」**。
上の例では勝者は $\lvert1\rangle$（0.466）で、$\lvert2\rangle$ は 0.158 で 3 位 → 断定されない。

そして **I 軸上どこを走査しても、$\lvert2\rangle$ の事後確率は 0.158 が最大値**だった。つまり

> **IQ 平面のどこに点が落ちても、$\lvert2\rangle$ が勝者になることはない。**

結果、B3 は 2000 ショット × 576 測定 = 115 万個を見て **1 個もリークと断定しなかった**（`flagged = 0`）。
これが「**一度も発火しない**」＝「フラグが 1 回も立たない」の意味。何もしないので **B3 ≡ B1**（LER も完全一致）。

> 選挙で言えば、候補 C がどの選挙区でも 15% は取るのに一度も 1 位になれず議席 0。
> 「C が勝ったらこうする」というルールは永久に発動しない。

#### (c) B3s = 勝者を決めず、0.158 を重みとして使う

$$p_S = \underbrace{(1-0.158)}_{\text{正常だった分}} \times \underbrace{0.4577}_{\text{正常なら取り違える確率}}
      + \underbrace{0.158}_{\text{リークだった分}} \times \underbrace{0.5}_{\text{リークなら値は無意味}}$$

「15.8% の確率でこの測定はゴミ（当てずっぽう = 0.5）、84.2% の確率で普通の読み出し」という混ぜ方。
断定しないので**勝者にならなくても $p_S$ は必ず動く**（0.4577 → 0.4644）。

#### (d) それでも B1 と差が出なかった本質

| IQ 点 | 取り違え確率 $p_2$ | リークの事後確率 | B1 の $p_S$ | B3 の $p_S$ | B3s の $p_S$ |
|---|---|---|---|---|---|
| I=0.0（境界の真上） | 0.4577 | **0.1581**（平面全体の最大値） | 0.4577 | 0.4577 | 0.4644 |
| I=0.3 | 0.1333 | 0.0916 | 0.1333 | 0.1333 | 0.1669 |
| I=1.0（状態の中心付近） | 0.0151 | 0.0060 | 0.0151 | 0.0151 | 0.0180 |

**2 列目と 3 列目が同じ向きに同じように動いている。** どちらも「境界（I=0）にどれだけ近いか」の関数でしかない。
リークの事後確率は、2 状態 LLR が既に言っていることの言い換えであり、**新しい情報が 0**。だから混ぜても結果が変わらない。

> **1 点だけでは、「正常な測定がたまたま境界近くに落ちた」のか「リーク中の測定」なのかを区別する手段が無い。**
> どちらも「真ん中あたりの点」という同じ見た目になる。

#### (e) なぜ 2 つとも必要だったか — 潰している仮説が違う

既存手法の失敗原因を 3 段階で切り分けている。

| 段 | 立てた問い | 手法 | 答え |
|---|---|---|---|
| 1 | Hanisch の手法（円形境界で検出 → フラグ）は効くか？ | **B2** | 効くどころか**有害**（0.172 > 0.159） |
| 2 | 悪いのは**境界が雑**だからか？ 理論的に最適な境界なら？ | **B3** | **一度も発火しない。**境界の問題ではない |
| 3 | 悪いのは**断定する**ことか？ 確率のまま渡したら？ | **B3s** | **変わらない。**判定の仕方の問題でもない |
| → | **では何が悪いのか** | | **1 点しか見ていないこと自体** |

この 3 段があって初めて「**時間方向（複数ラウンド）を見るしかない**」という結論が論理的に閉じる。
次に来るのが B4（8 ラウンドを見る古典最適 = §7.3）であり、時間 × 空間を使う学習型である。
**B3 は「無駄だったが記録した」のではなく、この切り分けの 2 段目として必要。**


### 7.3 B4（HMM）とは何か、なぜ必要か

**HMM = 隠れマルコフモデル。** 補助量子ビット 1 本について、各ラウンドの隠れ状態
$\ell_r \in \{\text{正常}, \text{リーク}\}$ を、観測した 8 ラウンド分の IQ 点から推定する。
遷移確率は**シミュレータが使っているリーク過程そのもの**、放射確率は $f^{(0)},f^{(1)},f^{(2)}$ そのもの。
前向き後向きアルゴリズムで $P(\ell_r \mid \mu_1,\dots,\mu_8)$ が**閉形式で厳密に**出る（学習は一切しない）。

**直感**：7.2 の通り 1 点では区別できない。**8 ラウンド見て「この量子ビットはずっと中央付近に落ち続けている」
なら、偶然ではなくリークだと分かる。** これが「持続性を使う」ということの最小の実装。

**必要な理由（査読対策）**：本研究の主張は「学習型がリークの持続性を捉える」。これに対する当然の反論が
**「持続性は 2 状態マルコフ連鎖なのだから、古典的な HMM 推論で厳密に解ける。Transformer は要らないのでは？」**。
B4 はその反論を**こちらで最強の形に作って先に置いたもの**。B4 に勝てないなら、主張は
「時間方向を使った」ではなく「時間 × 空間を同時に使った」に後退させねばならない。

**B4 にできないこと**（＝学習型の取り分）：
- 量子ビットを **1 本ずつ独立**に見る → **72 量子ビットのパリティ構造（符号）を使わない**
- 計算状態のビットを**等確率・ラウンド間独立**と仮定 → 実際の補助ビットの相関を使わない
- 実測：hybrid ④（空間のみ）0.1405 ≈ B4（時間のみ）0.1345、hybrid ①（両方）**0.1245**

**B4 のずるい所（論文で必ず書くこと）**：B4 は $p_{\rm leak}$, $p_{\rm seep}$, $f^{(0)},f^{(1)},f^{(2)}$ を
**真値で与えられている**。実機ではこれらは分からない。学習型はデータしか見ていない。
したがって **B4 と引き分けでも、実機を考えれば学習型の価値は残る**（モデル誤特定への頑健性 = 軸2 の (2)）。

## 8. $p_S$ をめぐる 6 つの疑問（2026-09-25 追記）

### 8.1 なぜ「硬判定が間違っている確率」という形で渡すのか

**BP-OSD はビットしか食べられないから。** アナログの (I,Q) をそのまま渡す口が無いので、
「このビットをどれだけ信用してよいか」を**数字 1 つ**に圧縮して渡す。それが $p_S$。

- $p_S = 0$ … このビットは絶対正しい
- $p_S = 0.5$ … このビットは何の情報も持っていない（**消去**）
- $p_S = 0.032$ を全部に … **B0**（信用度が一律＝アナログ情報を捨てた）
- 点ごとに計算 … **B1**。これが「soft 情報を使う」ということの全て

2 状態モデルの下では、この 1 つの数字が**十分統計量**（アナログ値から復号に必要な情報を余さず持つ）。
だから plan01 §6.1 の「(ii) soft 検出器が古典の上限」は誤りで、最強の古典比較対象は B1 になる。

### 8.2 「正常なのに $p_S=0.5$」と「リークで $p_S=0.5$」は何が違うのか

**値は同じだが、意味がまったく違う。**

| | 正常な測定の $p_S = 0.5$ | リーク測定の $p_S = 0.5$ |
|---|---|---|
| いつ起きるか | **点が境界上（I≈0）に落ちたときだけ** | **点がどこに落ちても常に** |
| 理由 | $\lvert0\rangle$ と $\lvert1\rangle$ の尤度が拮抗して決めかねる | 読み出し値が**真のパリティと無関係**だから |
| 点を動かすと | I=0.3 → 0.133、I=1.0 → 0.015 と**下がる** | **ずっと 0.5 のまま** |

つまり正常な測定の 0.5 は「**たまたま位置が悪かった**」、リークの 0.5 は「**位置に関係なく構造的に無意味**」。

### 8.3 リークの本当の害は「曖昧になること」ではなく「自信満々に間違えること」

$f^{(2)}$ は幅 σ=0.488 で広がるので、**リーク中でも点は境界から離れた所に落ちる**（40 万点の実測）：

| リーク測定について | 値 |
|---|---|
| 真の $p_S$ | **0.5**（読み出しは常に無意味） |
| B1 が付ける $p_S$ の平均 | **0.1442** |
| B1 が「$p_S<0.1$」＝それだけ自信ありと申告した割合 | **53.1%** |
| B1 が「$p_S<0.02$」＝ほぼ確実と申告した割合 | **21.3%** |
| $\lvert I\rvert > 0.7$（計算状態の中心寄り）に落ちる割合 | 15.2% |

**リーク測定の半分以上に、デコーダは「9 割以上信用してよい」と嘘を教えられている。**
曖昧な情報を受け取るのではなく、**間違った情報を高い確信度つきで受け取る**のが害の本体。
ORC（真のリークを 0.5 にする）が B1 から 0.053 も削るのは、この過信を消しているから。

そして **1 点しか見ないかぎり、この過信は直せない**（I=+1.0 に落ちたリーク点は、正常な自信ある点と見分けがつかない）。
直せるのは「同じ量子ビットを追って、読み出しが無意味な状態が続いていると気づく」ときだけ = §8.4。

### 8.4 ★ 核心：誰が何を見て確率を出しているか（1 ラウンドごとか、全ラウンドか）

| 手法 | 何を見て π（リーク確率）を出すか | ラウンド間で情報を受け渡すか |
|---|---|---|
| B1 / B3 / B3s | **その 1 点だけ** | **しない。**毎ラウンド事前確率 2.45% にリセット |
| **B4（HMM）** | **その量子ビットの 8 ラウンド全部** | **する**（前向き＋後ろ向き） |
| 学習型 ① | **1 ショット全部**（72 量子ビット × 8 ラウンド） | する（attention） |
| 学習型 ④ | そのラウンドの 72 量子ビットのみ | しない |

**「1 ラウンド目の事後確率を 2 ラウンド目の事前確率にする」という発想は正しく、それが B4 の前半（前向き＝フィルタリング）。**
ただし事後をそのまま事前にするのではなく、**マルコフ遷移を 1 回通す**：

$$\text{ラウンド } r+1 \text{ の事前確率} = \underbrace{\pi_r \times 0.801}_{\text{リークが継続}} + \underbrace{(1-\pi_r)\times 0.005}_{\text{新たにリーク}}$$

この漸化式の不動点が $\rho = 0.005/0.204 = 2.45\%$ ＝定常リーク率。
B4 はさらに**後ろ向き**もやる（ラウンド 3 の判定にラウンド 5〜8 の観測も使う）＝スムージング。

**実測（同じ量子ビットの 8 ラウンド）**：

```
--- 実際にずっとリークしていた量子ビット ---
  I 値      : +1.00 -1.25 +0.20 -0.28 -0.22 -0.11 -0.99 -0.11
  1点ごと π : 0.006 0.002 0.120 0.102 0.118 0.148 0.007 0.147   ← 全部低い。見つけられない
  HMM の π  : 0.042 0.083 0.656 0.786 0.817 0.805 0.691 0.677   ← 中盤以降ちゃんと気づく

--- 8 ラウンドすべて I=0（真ん中）に落ちた場合 ---
  1点ごと π : 0.158 0.158 0.158 0.158 0.158 0.158 0.158 0.158   ← 何回見ても 0.158 のまま
  HMM の π  : 0.962 0.993 0.999 0.999 0.999 0.999 0.993 0.962   ← ほぼ確実にリークと断定
```

**これが「持続性を使う」ことの正体。** 1 点ごとの手法は 8 回連続で真ん中に落ちても毎回 0.158 にリセットされる。
HMM は「8 回連続で真ん中は正常ではありえない」と積算して 0.999 に達する。

### 8.5 事後確率と「リークが起きる確率」の違い

**どちらも「リーク中である確率」。条件づけている情報が違うだけ。**

| | 値 | 意味 |
|---|---|---|
| 事前確率 $\rho$ | 2.45% | **何も見ていない**状態での平均的なリーク率 |
| 事後確率 $\pi$（1 点） | 0.158（I=0）／ 0.006（I=1） | **この点を見た後**の、この 1 測定についての確率 |
| 事後確率（HMM、8 ラウンド） | 0.999（8 回連続 I=0） | **8 ラウンド見た後**の、この 1 測定についての確率 |

同じ量が情報を足すたびに 0.0245 → 0.158 → 0.999 と更新される。
「密度は $f^{(2)}$ が 0.669 と最大なのに事前確率 2.45% で負ける」のもベイズの計算そのもの（尤度 × 事前 → 正規化）。

### 8.6 各式の出どころ

**$p_2 = 0.4577$（I=0）**：

$$L = \log\frac{f^{(0)}(0)}{f^{(1)}(0)} = \log\frac{0.0819}{0.0970} = -0.1697,\qquad
p_2 = \frac{1}{1+e^{|L|}} = 0.4577$$

0.5 ぴったりでないのは硬判定の境界が I=+0.0225 にずれている（β=0.05 の減衰）ため。**リークとは無関係な、2 状態だけの量**。

**$p_S = 1/(1+e^{|L|})$ の導出**：$\lvert0\rangle,\lvert1\rangle$ が等確率なら事後オッズ = 尤度比 $e^L$。
硬判定は大きい方を選ぶので、誤るのは小さい方が真だったとき → $\min(1,e^L)/(1+e^L) = 1/(1+e^{|L|})$。

**式19 $p' = p_S(1-p) + p(1-p_S)$**：測定ビットが反転する原因は「回路側の測定誤り（確率 $p$）」と
「読み出しの取り違え（確率 $p_S$）」の 2 つで、**両方起きれば元に戻る**。独立な 2 つの二値対称通信路の直列合成。

**B3s の $p_S = P(\text{逆の計算状態}\mid z) + \tfrac12 P(\text{リーク}\mid z)$**：
前半が「正常だが読み違えた」、後半が「リーク中なので 50% で外れる」。

> 理想化：$\lvert0\rangle,\lvert1\rangle$ を等確率と仮定。実際は X 補助 25% / Z 補助 50% が 1。
> 全手法で共通なので比較は公平だが論文には明記が必要（監査項目 10）。

### 8.7 $p_S = 0.5$ を入れて処理が壊れないか

**数値的には問題ない。** 事前確率 0.5 は LLR = 0 で発散も NaN もなく、H の列は元からあるので
**グラフ構造は一切変わらない**（Riverlane「追加ノード不要」）。

**統計的には壊れうる — それが B2 の失敗。** 0.5 にする＝その測定を消去することなので、
正常な測定を誤って 0.5 にすると本来使えた情報を捨てる。B2 は適合率 2.7%（フラグの 97% が誤報）で、
**リークを 1 個拾うごとに正常な測定を 36 個捨てていた** → 0.159 → 0.172 に悪化。

**逆に正しく 0.5 にするのはデコーダを助ける**：BP 収束率は B1 0.043 に対し **ORC 0.103 で全条件中最高**。
危険なのは 0.5 という値ではなく**誤報**。だから「断定せず確率で渡す」（B3s 以降）が安全。

### 8.8 学習型は時間関係を学習しているか

**① はしている。それが ④ との唯一の違い。**

- 入力は **576 トークン = 72 量子ビット × 8 ラウンド**を一度に全部。self-attention なので
  **同じ量子ビットのラウンド 3 と 5 のトークンが直接見合える**
- リークヘッドの出力は**トークンごと**＝ **(量子ビット, ラウンド) 1 個ごとに 1 確率**。形は B4 と同じ 576 個だが、
  **B4 が 1 本の量子ビットの 8 点しか見ないのに対し、① は 72 量子ビット × 8 ラウンド全部を見て各点の確率を出す**
- ④ は `mask` で同一ラウンド内に attention を制限 → そのラウンドの 72 点だけから判断（時間情報なし）
- **① は $p_{\rm leak}$ も $p_{\rm seep}$ も $f^{(2)}$ も教えられていない。**教師はリークの真偽ラベル $\ell$ だけで、
  「リークは続く」という性質はデータから学ぶしかない。**B4 は真の生成モデルを渡されている**ので、
  この点では学習型の方が条件が厳しい

→ 「hybrid ① 0.1245 vs B4 0.1345」は**モデルを知らされていない側が、知らされている側にわずかに勝っている**比較。
実機ではモデルパラメータは分からないので、この非対称性は論文で学習型に有利な材料として書ける。
